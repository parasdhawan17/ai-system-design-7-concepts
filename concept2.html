Concept 2 of 7

Fine-Tuning — Teach the Model How to Behave

Fine-tuning changes the model itself with examples. Use it for behaviour, format, and style — not for facts that change often.

THE BIG IDEA

The goal: teach how to behave, not what to know

Fine-tuning trains the model again, on your examples. The model learns a pattern of behaviour.

It learns how to answer. It is a poor way to teach it new facts.

WHEN TO USE IT

Good reasons to fine-tune

  • Consistent format: Always reply in one exact structure, like JSON with fixed fields.
  • Style and tone: Always sound like your brand. Short, formal, friendly — one voice.
  • Classification and extraction: Label tickets. Pull names, dates, and amounts from text.
  • Domain behaviour: Act like a legal assistant, a medical coder, or a support agent for one product.

You need good training examples. Many teams start with hundreds to thousands of clean input–output pairs. Bad examples teach bad behaviour.

RAG vs FINE-TUNING

The comparison every interview asks

RAGFine-tuning
ChangesThe context at answer timeThe model itself

Common use togetherMost real systems use both: fine-tune for behaviour, RAG for knowledge.
COST TRICK + MISTAKE

LoRA, PEFT, and the classic error

LoRA / PEFT means parameter-efficient fine-tuning. You train only a small added part, not the whole model. Training is much cheaper and faster. Results are often close to full fine-tuning.

Common mistakeDo not fine-tune a model just because it does not know information that changes often. The model will learn stale facts. Use RAG for that job.
DEEP DIVE · THE PROCESS

How fine-tuning works, step by step

  1. Collect examples: Real inputs with ideal outputs. Use your best human answers, not raw logs.
  2. Clean the data: Remove wrong answers, private data, and duplicates. Quality beats quantity. 1,000 clean examples beat 10,000 messy ones.
  3. Format: Put examples in one fixed format, usually instruction + answer pairs, or chat messages.
  4. Split: Keep a test set aside. Never train on your test examples.
  5. Train: Run a few passes (epochs) over the data. Watch the test score. More passes can cause overfitting: the model memorizes examples and gets worse on new ones.
  6. Evaluate: Compare base model vs tuned model on the same eval suite.
  7. Deploy and monitor: Ship to a small group first. Watch real feedback.
DEEP DIVE · METHODS

Full fine-tuning vs LoRA

Full fine-tuningLoRA / PEFT
What changesAll model weightsA small added adapter only
CostHigh. Needs big GPUs and more time.Low. Often 10 to 100 times cheaper.
ResultStrongest change possibleClose to full for most behaviour tasks
RiskCatastrophic forgetting: the model loses old skills while learning new ones.Lower risk. Base skills stay mostly intact.
OperationsOne full model copy per taskOne base model + many small adapters. Easy to swap.

SFT (supervised fine-tuning) is the main method: learn from correct examples. RLHF and DPO come after: the model learns from preferences — this answer is better than that one. Use them to polish tone and helpfulness.

WORKED EXAMPLE

Support replies in one format

Goal: every reply must be: greeting, answer, next step, sign-off.

1. Collect 800 past replies that agents rated as excellent.
2. Rewrite them into the target format.
3. Fine-tune with LoRA on these examples.
4. Eval: format score 61% -> 97%. Fact score unchanged.
5. Facts still come from RAG. Format comes from fine-tuning.

This split is the classic design: fine-tuning owns the shape, RAG owns the facts.

MISTAKES AND FIXES

Four classic errors

MistakeFix
Training on raw chat logs with bad answers insideCurate. Only ideal outputs teach.
Fine-tuning to add facts that change weeklyUse RAG for facts. Fine-tune only stable behaviour.
No test set. “It feels better.”Hold out a test set. Run the same eval before and after.
One giant training run, no checkpointsSave checkpoints. Pick the best test score, not the last run.
Design checklistProblem is behaviour, not fresh facts · examples are clean and ideal · test set is held out · LoRA first, full only if needed · eval before and after · version the dataset and the model together.

Interview Q&A

  1. Prompting, RAG, or fine-tuning — how do you choose?
  2. What is catastrophic forgetting?
  3. How much data do you need?
Prompting, RAG, or fine-tuning — how do you choose?

Start with prompting: cheapest and fastest. Add RAG when the model needs private or fresh knowledge. Fine-tune when behaviour must be consistent at scale and prompting keeps failing — strict format, style, or a narrow skill.

What is catastrophic forgetting?

When fine-tuning on new data makes the model lose old abilities. It happens most with full fine-tuning and high learning rates. LoRA, lower learning rates, and mixing some general examples into the data reduce it.

How much data do you need?

For a narrow behaviour, hundreds of excellent examples can work. For a broad skill, thousands or more. Data quality matters more than raw count, and a held-out test set tells you if you have enough.

Quick quiz

  1. Your model must answer with today’s prices. Fine-tuning or RAG?
Show answer

RAG. Prices change often. Fine-tuning would freeze old prices into the model. Fine-tune for behaviour; retrieve for fresh facts.
