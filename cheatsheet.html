Cheat Sheet

Read this page 10 minutes before an interview.

The 7 concepts in one table

ConceptRemember this
1. RAG — Give the Model the Right KnowledgeRetrieval-Augmented Generation. The model does not know your data. You fetch the right data and give it to the model at answer time.
2. Fine-Tuning — Teach the Model How to BehaveFine-tuning changes the model itself with examples. Use it for behaviour, format, and style — not for facts that change often.
3. Evals — Know If the System WorksEvaluations are tests for AI systems. They show if a change helped or hurt, before users find out.
4. Agents — Systems That Plan, Use Tools, and ActAn agent is more than a chatbot. It plans steps, calls tools, checks results, and keeps going until the job is done.
5. Caching — Make It Faster and CheaperDo not pay twice for the same work. Cache embeddings, retrieval, answers, and tool results — and know when a cache entry dies.
6. User Feedback Loops — Learn From Real UsersReal users find failures your tests missed. Collect their signals, find the root cause, fix it, and turn the fix into an eval.
7. Guardrails — Control What the System Can DoGuardrails set the limits. They check inputs and outputs, protect data, and keep humans in charge of risky actions.

Sample answer: “Design an AI support system”

  1. Start with RAG over help docs and tickets. Hybrid search, reranking, citations.
  2. Fine-tune only for tone and format, if prompting is not enough.
  3. Use an agent loop for actions: look up order, start refund — with step and cost limits.
  4. Add caching: semantic cache for common questions, with a short TTL.
  5. Build evals before launch: 20–50 real tasks, code + model graders, pass^k for reliability.
  6. Ship with guardrails: PII checks in and out, injection defence, human approval for big refunds.
  7. Close the feedback loop: every thumbs down is investigated and becomes a new eval.

Lines that win points

  • “Good retrieval = good context = good answer.”
  • “Fine-tune for behaviour. Retrieve for fresh facts.”
  • “Grade the outcome, not the chat text.”
  • “75% per trial is only 42% pass^3. Consistency is the real bar.”
  • “Freshness beats speed. A fast stale answer is wrong.”
  • “Feedback is a clue, not ground truth.”
  • “The model can propose. The application decides.”

Glossary — key words in simple English

WordMeaning
EmbeddingNumbers that capture the meaning of a text. Similar meaning, similar numbers.
ChunkA small piece of a document, cut for search.
Vector databaseA database that finds texts by meaning, using embeddings.
RerankerA stricter model that re-sorts search results and keeps the best.
GroundingForcing answers to use only the given sources.
HallucinationA confident answer that is not true and not in the sources.
LoRA / PEFTCheap fine-tuning: train a small adapter, not the whole model.
SFTSupervised fine-tuning: learn from correct examples.
RubricA scoring guide that tells a grader what good means.
pass@k / pass^kAt least 1 success in k tries / all k tries succeed.
SaturationAn eval is so easy that scores stop teaching you anything.
Scaffold / harnessThe system around the model that runs tools, loops, and limits.
IdempotentSafe to repeat: a retry does not charge twice or book twice.
TTLTime to live: how long a cache entry survives.
Semantic cacheA cache that matches by meaning, not by exact text.
Prompt injectionHostile text that tries to act as an instruction.
PIIPersonal data: names, emails, card numbers, IDs.
Red teamingAttacking your own system on purpose, to find weak points first.

Rapid-fire facts

  • RAG debug order: retrieval first, prompt second.
  • Chunk start point: 256–1,000 tokens, 10–20% overlap.
  • Rerank: search returns 20–50, prompt uses top 3–8.
  • Fine-tuning data: quality beats quantity. Curate ideal answers only.
  • LoRA is often 10–100× cheaper than full fine-tuning.
  • First eval suite: 20–50 tasks from real failures.
  • 0% across many trials usually means a broken task, not a weak model.
  • Agent reliability: 95% per step × 20 steps ≈ 36%. Verify, checkpoint, retry.
  • Cache rule: freshness beats speed, always.
  • Feedback rule: a thumbs down is a clue, not a diagnosis.
  • Guardrail rule: prompts advise, code enforces.
