The 7 concepts

Read them in order. Together they describe one complete AI system.

CONCEPT 1

RAG — Give the Model the Right Knowledge

Retrieval-Augmented Generation. The model does not know your data. You fetch the right data and give it to the model at answer time.

  • Fetch first, then answer
  • Chunking and embeddings decide quality
  • Hybrid search + reranking
  • Keep documents fresh
Open concept 1 → CONCEPT 2

Fine-Tuning — Teach the Model How to Behave

Fine-tuning changes the model itself with examples. Use it for behaviour, format, and style — not for facts that change often.

  • Behaviour, not knowledge
  • Format, tone, classification, extraction
  • LoRA / PEFT cuts training cost
  • Do not fine-tune for changing facts — use RAG
Open concept 2 → CONCEPT 3

Evals — Know If the System Works

Evaluations are tests for AI systems. They show if a change helped or hurt, before users find out.

  • Task, trial, grader, transcript, outcome
  • 3 graders: code, model, human
  • Capability vs regression evals
  • pass@k vs pass^k
Open concept 3 → CONCEPT 4

Agents — Systems That Plan, Use Tools, and Act

An agent is more than a chatbot. It plans steps, calls tools, checks results, and keeps going until the job is done.

  • The loop: plan → act → observe → repeat
  • Brain = model, hands = tools
  • Memory and a harness (scaffold)
  • Errors compound — add checkpoints
Open concept 4 → CONCEPT 5

Caching — Make It Faster and Cheaper

Do not pay twice for the same work. Cache embeddings, retrieval, answers, and tool results — and know when a cache entry dies.

  • Cache at 4 layers
  • Exact cache vs semantic cache
  • Invalidation is the hard part
  • Freshness beats speed
Open concept 5 → CONCEPT 6

User Feedback Loops — Learn From Real Users

Real users find failures your tests missed. Collect their signals, find the root cause, fix it, and turn the fix into an eval.

  • Signals: corrections, retries, escalations, drop-offs
  • Feedback is a clue, not the truth
  • Loop: feedback → root cause → fix → eval
  • Feedback becomes permanent knowledge
Open concept 6 → CONCEPT 7

Guardrails — Control What the System Can Do

Guardrails set the limits. They check inputs and outputs, protect data, and keep humans in charge of risky actions.

  • Layers: input, model, output, application
  • Input: injection, PII, auth checks
  • Output: schema, PII, safety checks
  • The model proposes. The application decides.

How they fit together

RAG gives the model knowledge. Fine-tuning shapes its behaviour. An Agent uses both to do work. Caching makes it fast and cheap. Evals prove it works. Feedback loops make it better from real use. Guardrails keep it safe.
