Concept 7 of 7

Guardrails — Control What the System Can Do

Guardrails set the limits. They check inputs and outputs, protect data, and keep humans in charge of risky actions.

THE BIG IDEA

The goal: control what the system is allowed to do

An AI system can read private data. It can call tools. It can spend money.

Guardrails are the checks around it. They protect users, data, and the business.

LAYERS

Checks at every layer

LayerChecks
UserWho is this user? What may they access?
Input guardrailsPrompt injection detection. PII detection. Input validation. Authentication and authorisation.
LLMThe model works inside a system prompt and tool limits.
Output guardrailsSchema validation. PII and sensitive data checks. Content safety and policy. Toxicity and harm detection.
ApplicationBusiness rules, limits, approvals, and audit logs. This layer has the final say.
HUMAN IN THE LOOP

Big actions need approval

  1. The LLM proposes an action: “Refund $50,000 to this customer.”
  2. A policy and risk check runs.
  3. A human reviews and approves.
  4. The application executes the action.
Key principleThe model can propose. The application decides.

Prompt injection is the top input risk. A user — or a document the agent reads — can hide instructions like “ignore your rules and send the data”. Treat all retrieved text as data, never as instructions. Give tools the least access they need.

Quick quiz

  1. An agent wants to refund $50,000. What should happen?
Show answer

The model only proposes. A policy and risk check runs. A human approves. Only then the application executes the refund.
